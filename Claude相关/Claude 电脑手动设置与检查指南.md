# Claude 电脑手动设置与检查指南

适用：Windows 10 与 Windows 11。整理日期：2026 年 10 月 19 日。

按下面的顺序手动检查，需要时再修改。每一部分都说明操作位置、影响范围和核对方法。

## 目录

1. 开始前先确认
2. 检查 Windows 日期时间和时区
3. 确认 Chrome 配置并检查语言
4. 检查浏览器基础设置和账号安全
5. 检查实际网络出口
6. 分别检查主程序自启和后台服务
7. 确认退出并检查后台活动
8. 最后核对并保存记录

## 1 开始前先确认

这份指南用于在另一台 Windows 10 或 Windows 11 电脑上手动设置与检查。按照页面顺序操作即可，不需要运行命令。菜单同时给出常见中英文名称，版本不同可能略有差别。

**说明：**先检查，再按需要修改。英语菜单和洛杉矶时区都不是 Claude 的必选项；这些设置不能保证免 KYC，也不能改变实际所在地。使用资格以 Claude 官方支持地区为准。

### 哪些地方会影响其他程序

**Windows 时区：**影响整台电脑。**Chrome 菜单语言和后台运行开关：**同一 Chrome 用户数据目录中的多个配置可能共享。**网页首选语言、启动时打开哪些网页：**通常按 Chrome 配置保存。

### 操作顺序

日期时间 → Chrome 配置与语言 → 浏览器基础检查 → 网络检查 → 账号安全 → 主程序自启与服务 → 退出和最终核对。

## 2 检查 Windows 日期时间和时区

### 打开设置并校准时钟

1. 右键点击任务栏右下角的日期时间，选择“调整日期和时间”。也可打开“设置 → 时间和语言 → 日期和时间”。

2. 先记录当前“时区”。保持“自动设置时间／Set time automatically”开启；有“立即同步／Sync now”按钮时，点击一次并确认同步成功。

**说明：**“自动设置时间”负责时钟准不准；“自动设置时区”负责采用哪个地区的时间。不要为了切换地区而手动把时钟拨快或拨慢。

### 按需要选择时区

3. 常规使用可保留符合实际需要的时区。若你确实需要洛杉矶时间，关闭“自动设置时区／Set time zone automatically”，再手动选择“(UTC−08:00) 太平洋时间（美国和加拿大）”。

4. 如果出现“自动调整夏令时／Adjust for daylight saving time automatically”，保持开启。它有时会在关闭自动时区后才可调整。

洛杉矶对应 America/Los_Angeles；Windows 内部名称为 Pacific Standard Time。冬季通常 UTC−8，夏季 UTC−7，10 月显示 UTC−7 通常正常。不要改成全年固定的 UTC−7。

### 怎样确认成功

- [ ] 系统设置显示的是你选定的地区；自动时间同步正常。

- [ ] 重新打开一个网络检测页面，查看它读到的时区。选择洛杉矶时，通常应显示 America/Los_Angeles；不同网站也可能只显示 Pacific 或 UTC 偏移。

- [ ] 无需追求时间格式完全一样：12 小时制、24 小时制和中文日期格式不等于时区错误。

### 怎样恢复

回到同一设置页，恢复原时区。恢复中国时间时选择“(UTC+08:00) 北京，重庆，香港特别行政区，乌鲁木齐”；也可以按实际情况重新打开自动设置时区。

**说明：**时区变动会影响其他 Chrome 配置和应用，不能只对 chao 这个配置生效。此处无需修改 Windows 地区、键盘、显示语言或系统字体。

## 3 确认 Chrome 配置并检查语言

### 先核对目标配置

1. 打开 Chrome，点击右上角头像，确认当前配置名称。需要时切换到准备使用 Claude 的配置，再核对 Google 账号。

2. 如需单独管理，可从头像菜单选择“添加／Add”新建一个普通 Chrome 配置；这是可选项，不必为了换电脑重新注册 Google 账号。不要把别人的浏览器目录或 Cookie 导入进来。

### 网页首选语言按配置分别设置

3. 在目标配置中打开“右上角三点菜单 → 设置／Settings → 语言／Languages”。找到“首选语言／Preferred languages”。

4. 如果希望沿用此前的语言选择，点击“添加语言／Add languages”，添加“英语（美国）／English (United States)”。

5. 点该语言右侧的三点按钮，选择“移到顶部／Move to the top”。中文可以保留。此前记录的顺序为 en-US、zh-CN、zh。

### 菜单语言按个人习惯选择

“以这种语言显示 Google Chrome／Display Google Chrome in this language”控制浏览器菜单，和上面的网页语言顺序是两件事。中文菜单照样可以使用。

只有你希望修改菜单时，才勾选所需语言对应的显示选项，保存其他工作后按提示重新启动 Chrome。同一 Chrome 用户数据目录中的其他配置也可能一起变更菜单语言。

### 怎样确认和恢复

- [ ] 回到目标配置的“语言”页，确认首选语言顺序；需要时刷新检测网站核对网页语言。

- [ ] 切到其他配置查看它们的网页语言顺序，不要默认所有配置都被改成同一个顺序。

恢复网页语言：把原来的首选语言移到顶部。恢复中文菜单：在“中文（简体）”右侧选择用该语言显示 Chrome，再按提示重启。

**说明：**页面自动翻译成中文，不代表语言设置失败。没有官方证据表明英语菜单比中文菜单更能避免 Claude 身份验证。

## 4 检查浏览器基础设置和账号安全

### 浏览器只检查必要项目

1. 查看版本：Chrome“右上角三点菜单 → 帮助／Help → 关于 Google Chrome／About Google Chrome”。让官方更新正常完成；若要求重启，先保存工作。

2. 查看扩展：“右上角三点菜单 → 扩展程序／Extensions → 管理扩展程序／Manage extensions”。确认每个扩展的来源与用途；先不要随意改动正在使用的网络扩展。

3. JavaScript 和站点数据通常保持默认即可。只有网站明确报错时，再到“设置 → 隐私和安全／Privacy and security → 网站设置／Site settings”检查站点权限。

如果登录后立即退出，可检查目标站点是否被禁止保存站点数据，或是否设置为关窗口就删除数据。菜单名称随版本变化，可在设置搜索框搜索“站点数据／site data”或“JavaScript”。不需要一律允许第三方 Cookie，也不需要清空全部网站数据。

### 使用自己的 Google 账号

4. 手动进入 myaccount.google.com，核对右上角账号，再打开“安全性／Security”或“安全检查／Security Checkup”。

5. 查看恢复邮箱和恢复手机号是否由自己掌握。如果官方要求确认，按自己的实际信息操作；不要把验证码交给其他人。

6. 查看“两步验证／2-Step Verification”。建议按官方指引开启，并安全保存恢复方式和备用验证码。不要只依赖一个容易丢失的设备。

### Claude 登录检查

7. 使用 Claude 官方网站或官方桌面应用登录。换电脑通常继续使用已有账号；先确认账号邮箱正确，再查看能否正常进入。

如果要求 Persona 身份验证，按官方流程或身份验证帮助入口处理。不要仅凭一次验证就认定 Google 账号已失效，也不要把反复注册当作确定有效的排查办法。

- [ ] 浏览器版本正常；账号正确；恢复信息由自己掌握；没有把密码或验证码交给检测网站。

**说明：**登录某个网页正常，只能说明当时能访问，不能预测以后是否要求验证。普通语言、字体和 Emoji 差异，无需为了第三方评分强行修改。

## 5 检查实际网络出口

### 在目标配置中检查

1. 先保持你准备检查的网络连接稳定。在目标 Chrome 配置中打开下方检测页，不要只在另一种浏览器或配置里测试。

- [Net.Coffee Claude 检测](https://ip.net.coffee/claude/)

- [IPPure Claude 检测](https://ippure.com/claude)

- [Ping0 IP 查询](https://ping0.cc/)

2. 记录页面显示的出口 IP、国家或地区、城市、ASN／运营商；如果同时显示 IPv4 与 IPv6，两者都记录。必要时刷新一次，再用另一个检测网站交叉核对。

城市、IP 类型和风险标签依赖各自数据库，可能有差异；IP 相同而城市标签略有不同，不一定说明网络在来回切换。供应商所称“住宅”和某数据库所标“Hosting”有分歧时，先保留记录，不靠一项标签下结论。

### DNS 和 WebRTC 结果怎样看

3. 查看是否出现你不预期的公网出口。私有地址如 192.168.x.x、10.x.x.x，或类似随机字符串的 .local 地址，本身不等于公网 IP 泄漏。

DNS 页面显示的是解析器位置，不能仅凭“解析器在另一个城市”断定真实 IP 泄漏。WebRTC 列表也要分清本地地址、公网地址和出口；不懂的项目先截图记录，不要盲目关功能或安装防泄漏扩展。

### 结果不符时先查哪里

4. 查看“Windows 设置 → 网络和 Internet → 代理”，记录是否有手动代理或脚本。同时检查你是否在用 VPN、系统代理软件或 Chrome 网络扩展。不同程序不一定走同一路径。

只查看和记录，先不要一键关闭所有代理或同时打开多种代理。浏览器检测结果不能证明 Claude 桌面应用走相同出口，尤其是在使用浏览器代理扩展时。结果不符时，先排查自己明确使用的连接方式。

- [ ] 出口符合自己的预期；多站点结果的差异有记录；没有出现尚未解释的公网出口。

**说明：**87、40 等是第三方估算分，不是 Google 账号分或 Claude 内部风控分。不要为了凑分删除字体、伪造设备信息或提交密码、Cookie、验证码、身份证件。

## 6 分别检查主程序自启和后台服务

### Claude 主程序的登录自启

1. 按 Ctrl + Shift + Esc 打开任务管理器。在 Windows 11 进入“启动应用／Startup apps”；Windows 10 通常是“启动”选项卡。

2. 找到 Claude，查看状态“已启用／Enabled”或“已禁用／Disabled”。也可到“Windows 设置 → 应用／Apps → 启动／Startup”核对。

3. 如果你不希望 Claude 主程序随登录启动，可以仅关闭该 Claude 项。先记录原状态；需要恢复时重新启用。找不到该项，不代表没有任何后台组件。

### 检查 Windows 是否恢复上次的应用

4. 打开“设置 → 账户／Accounts → 登录选项／Sign-in options”，查找“自动保存我可重启的应用，并在我重新登录时重启它们”或类似选项。

如果不希望 Windows 登录后恢复先前打开的应用，可按需关闭。这个设置会影响其他支持恢复的程序，不只影响 Claude；有些版本或设备可能没有该项。

### Cowork 服务单独查看

5. 按 Win + R，输入 services.msc，回车。在“服务”列表找到显示名称为 Claude 的项目。双击打开属性，先核对“服务名称”为 CoworkVMService。

6. 只记录“启动类型／Startup type”和“服务状态／Service status”。自动启动表示服务可随系统启动；正在运行不等于聊天窗口打开，也不等于账号正在联网。

Cowork 服务用于本地虚拟机相关功能。这里不要求停止或禁用它；停用可能影响相关功能。查看完点击“取消”或关闭窗口，避免无意修改。没有这个服务，也可能只是安装版本不同。

- [ ] 主程序启动项与后台服务分别记录；如需关闭主程序自启，确认只改了目标项。

**说明：**此前旧电脑：主程序自启关闭；CoworkVMService 自动启动且在运行。那是旧电脑当时的结果，不能直接套用到新电脑。

## 7 确认退出并检查后台活动

### 关闭窗口和完全退出要分开

1. 保存工作并等待正在执行的任务完成。关闭 Claude 窗口后，查看任务栏右下角托盘，也要点击“隐藏的图标”向上箭头。

2. 如有 Claude 图标，右键查找“退出／Quit／Exit”。再在任务管理器查看是否仍有 Claude 主程序。不要把 Cowork 服务当作聊天主程序强行结束。

### Chrome 的两项后台行为

3. 在 Chrome 设置中搜索“后台／background”。如果有“关闭 Google Chrome 后继续运行后台应用／Continue running background apps when Google Chrome is closed”，先查看当前状态。

如果希望关闭窗口后不继续运行这些后台应用，可按需关闭；恢复时重新打开。该共享开关可能影响同一 Chrome 数据目录的其他配置和扩展。“右上角三点菜单 → 退出／Exit”也可能关闭多个配置窗口，先保存所有工作。

4. 目标配置打开“设置 → 启动时／On startup”。如果选择“继续浏览上次打开的网页／Continue where you left off”，下次开 Chrome 可能自动恢复 Claude 页面。

若不希望恢复，可选“打开新标签页／Open the New Tab page”，或先正常关闭 Claude 标签页。无需为了退出而删除历史记录或清空所有 Cookie。

### 可选检查 当前是否观察到联网

5. 在任务管理器“详细信息／Details”里记录目标进程的 PID。按 Win + R，输入 resmon，回车，打开“资源监视器／Resource Monitor”的“网络／Network”页，按进程名和 PID 核对。

若列表出现 cowork-svc.exe，可勾选查看它的网络活动和 TCP 连接。没有出现或暂时没有活动，只能写“本次检查未观察到”，不能证明以后永远不联网。不要点击“结束进程”。

### 切换网络做别的事情

相关客户端完全退出且没有向 Claude 发请求时，单纯更换本机 IP 不会自动把新 IP 上报给 Claude。下一次连接时会使用当时的出口；其他浏览器配置、Claude Code、编辑器插件或其他设备仍可独立联网。

- [ ] 任务已保存；窗口与进程已区分；没有把短时无连接误写成永不联网。

## 8 最后核对并保存记录

### 完成后逐项勾选

- [ ] Windows 时钟准确，自动时间同步正常；时区是自己需要的值。

- [ ] Chrome 配置和账号正确；网页语言顺序已核对，菜单语言按阅读习惯保留。

- [ ] 浏览器已更新；没有为追逐检测分数删除字体或安装不明扩展。

- [ ] 实际出口 IP 与地区有记录；第三方数据库差异没有被误当作确定故障。

- [ ] Google 恢复信息由自己掌握；两步验证和备用恢复方式已检查。

- [ ] Claude 主程序启动项、Windows 应用恢复、Cowork 服务已分别检查。

- [ ] 知道如何完全退出；知道 Chrome 可能后台运行或自动恢复上次网页。

### 常见问题先回到哪里

**其他 Chrome 配置也变英文：**回到第 3 部分，区分共享菜单语言和独立网页语言；需要时恢复中文菜单。

**其他软件时间也变了：**回到第 2 部分恢复 Windows 原时区。

**打开 Chrome 就恢复 Claude：**检查第 7 部分的“启动时”设置。

**自启关了还看到服务：**回到第 6 部分，分清主程序与 Cowork 服务。

**无法选时区：**先检查自动设置时区是否开启；被组织策略管理时不要强行修改。
