# Claude 电脑与浏览器设置笔记

**用途：在另一台 Windows 电脑上，复查浏览器配置、网络、账号安全和后台运行情况。**

整理日期：2026 年 10 月 19 日。下面的本机检查结果来自此前会话，主要检查于 2026 年 10 月 15 日；它们是当时的记录，不代表今天或另一台电脑的状态。本次整理没有重新检查或修改电脑设置。

这份笔记记录实际操作和可复查的方法。没有任何一项设置能够保证不出现 Persona 身份验证。美国 Google 账号、美国出口 IP、英语和洛杉矶时区，也不能代替 Claude 对实际使用地区的要求。

## 1. 换电脑时，先照这张清单检查

- [ ] 确认打开的是要使用的 Chrome 配置，核对右上角头像、配置名称和登录邮箱。
- [ ] 区分 Chrome 菜单语言与网页首选语言，避免误改其他配置。
- [ ] 查看 Windows 当前时区；只有确实需要时再调整，并记下原值。
- [ ] 如需排查网络，记录浏览器实际出口 IP、地区和网络运营商，不只看代理商宣传。
- [ ] 在 Google 官方账号页面确认账号能正常打开，检查恢复信息和两步验证建议。
- [ ] 换电脑通常继续登录已有账号即可，不必仅因换电脑重新注册 Google 或 Claude。
- [ ] 查看 Claude 主程序的登录自启设置，并单独查看 Cowork 后台服务。
- [ ] 切换网络做其他事情前，分清“关闭窗口”和“完全退出”。

**建议顺序：确认配置 → 记录原设置 → 检查 → 有具体需要时再修改。不要一次改很多项，再用结果猜原因。**

## 3. 先选对 Chrome 配置

1. 打开 Chrome，点击右上角头像。
2. 选中准备用于这个账号的配置；配置名称和 Google 邮箱都核对一次。
3. 如果让助手操作浏览器，先让助手报出它实际连接到的配置名称，再继续。
4. 若连接到另一个配置，先纠正连接，不要先修改再补救。

之前曾把“超”和“工作／chao”混淆，这也是后来需要澄清语言影响范围的原因。**另一台电脑上的配置名称可能不同，不要照抄名称。**

当时浏览器工具无法访问部分 Chrome 内部设置页，因此语言设置有一部分是你手动完成的。新电脑上若也出现工具访问限制，可由你在设置界面操作，不应改用其他途径绕过限制。

## 4. Chrome 语言：菜单和网页是两回事

| 设置 | 作用 | 影响范围 |
| --- | --- | --- |
| Chrome 显示／菜单语言 | 决定设置、菜单等界面用什么语言 | Windows 上，同一 Chrome 用户数据目录中的多个配置可能一起变化 |
| 网页首选语言 | 向网站表达优先使用哪种语言 | 按 Chrome 配置分别保存 |
| Windows 时区 | 系统和浏览器通常据此显示时间与时区 | 整台电脑，包括其他浏览器配置和应用 |

### 如果需要保留此前目标配置的网页语言顺序

1. 先切到目标 Chrome 配置。
2. 右上角 **⋮ → 设置／Settings → 语言／Languages**。
3. 在“首选语言／Preferred languages”中添加“英语（美国）／English (United States)”。
4. 点击该语言右侧的 **⋮ → 移到顶部／Move to the top**。
5. 中文可以保留。此前实测顺序是 `en-US, zh-CN, zh`。

不要把“移到顶部”与“用这种语言显示 Google Chrome”混为一项。后者控制菜单界面，可能影响同一套 Chrome 的其他配置，并可能要求重新启动 Chrome。

**菜单保持中文也可以。没有官方证据表明，把 Chrome 菜单改成英文就能防止 Claude 要求身份验证。** 如果只是自己读起来方便，可以在“中文（简体）”右侧菜单选择用它显示 Chrome；先保存工作，再按界面提示重启。

## 5. Windows 时区：此前改了什么，怎样恢复

此前原始时区是 **China Standard Time**，即北京／上海时间。最终按你的要求设为 **Pacific Standard Time**，对应美国洛杉矶时区。

注意：Windows 名称中虽然有 Standard，但该时区支持夏令时。洛杉矶通常冬季为 UTC−8，夏季为 UTC−7；此前 10 月检查时为 UTC−7。**不要把洛杉矶理解为全年固定 UTC−8。**

### 如果新电脑确实需要使用洛杉矶时间

1. 打开 **Windows 设置 → 时间和语言 → 日期和时间**。
2. 先记下原时区。
3. 若要手动选时区，关闭“自动设置时区”，选择“太平洋时间（美国和加拿大）”。不同 Windows 版本的名称可能略有差异。
4. 若界面提供“自动调整夏令时”，保持开启。
5. “自动设置时间”通常可以保持开启；时钟是否准确和时区选择是两件事。

### 恢复中国时间

在同一位置选 **“(UTC+08:00) 北京，重庆，香港特别行政区，乌鲁木齐”**；也可以按你的实际情况恢复自动设置时区。

**时区不能只对 chao 这个 Chrome 配置生效。** 此前做的是 Windows 系统级调整。换电脑时按实际需要决定是否调整，不必把它当作 Claude 注册的必做步骤。

## 6. 网络怎么检查，第三方分数怎么看

此前用过这些网站：

- [Net.Coffee Claude 检测](https://ip.net.coffee/claude/)
- [IPPure Claude 检测](https://ippure.com/claude)
- [Ping0 IP 查询](https://ping0.cc/)

在目标浏览器配置中打开，重点记录：

1. 网站实际看到的出口 IP，是否与你预期的一致。
2. 出口所在国家、城市、ASN／运营商；数据库可能有延迟或差异。
3. 系统时区、网页语言是否符合你自己设定的值。
4. 检测页是否报告 DNS／WebRTC 等网络路径异常；没有报错也不代表全面保证。

不要向这些第三方网站提交 Google／Claude 密码、验证码、Cookie 或身份证件。它们不是 Anthropic 的账号诊断后台。

### 此前本机的检测记录

| 项目 | 当时看到的结果 | 应怎样理解 |
| --- | --- | --- |
| 出口位置 | 美国洛杉矶 | 这是当时网页观察到的出口位置 |
| ASN／网络 | AS2914，NTT America | 这是网络归属记录，不能单独证明住宅属性 |
| IP 类型 | 供应商宣传为住宅，某检测库标为 Hosting | 标签存在分歧；不能只选一个标签就下结论 |
| Cookie | 启用 | 只是浏览器基础功能检查 |
| 时区与语言 | 洛杉矶；`en-US, zh-CN, zh` | 是当时该配置的结果，另一台电脑需重查 |
| DNS／WebRTC | 检测页没有报告明显泄漏 | 只代表该检测当时未发现问题 |
| 87 分 | Net.Coffee 的第三方 IP 估算分 | 不是 Google 账号分，也不是 Anthropic 内部风控分 |
| 40 分 | IPPure 的第三方环境估算分 | 不是 Claude 实际 KYC 决策分 |

IPPure 当时把中文次选语言计为 17、中文字体计为 20、Windows／微软 Emoji 风格计为 3；洛杉矶时区等项目计为 0。这只是它自己的计分规则。**不建议为了追逐这类分数去删除系统字体、伪造 Emoji 或安装不明扩展。**

此次并没有确定原账号为什么触发 KYC。换账号后成功注册，也不能反向证明问题一定出在旧 Google 账号、IP、字体或语言中的某一项。

## 7. Google 与 Claude 账号：检查到什么程度

Google 官方页面：

- [Google 账号管理](https://myaccount.google.com/)
- [Google 安全检查](https://myaccount.google.com/security-checkup)

此前新 Google 账号能正常进入这些页面，当时没有看到账号停用或强制验证拦截。安全检查里有恢复信息确认、两步验证等建议。我们只查看了状态，没有替你执行安全设置更改。

在另一台电脑上，可以核对恢复邮箱、恢复手机号是否仍由自己掌握，并按官方建议设置两步验证。验证码和恢复码由你自己保管。**能正常进入 Google 账号页面，不等于一定能注册 Claude，也不保证未来不会要求验证。**

原 Claude 账号当时显示 Persona 身份验证未完成，没有据此确认账号已“废了”。新 Claude 账号当时不跳 KYC，是你报告的注册结果。若以后出现验证，应按 Claude 官方页面要求处理；不要把反复注册新号当成确定有效的解决办法。

## 8. 开机自启：主程序与 Cowork 服务分别检查

### 此前电脑的实际结果

| 对象 | 当时的设置／状态 | 说明 |
| --- | --- | --- |
| Claude 桌面主程序 | 登录自启关闭；检查时未运行 | 没有发现主程序会随登录自动打开 |
| Claude Cowork 后台服务 | 自动启动；检查时正在运行 | 服务名称为 `CoworkVMService`，与聊天窗口自启是两回事 |
| 服务网络连接 | 几次短时检查未发现连接或子进程 | 不代表该服务永远不会联网 |

当时同时检查了常见启动注册项、启动文件夹、计划任务和安装包启动任务。主程序的 `ClaudeStartup` 用户状态为 `State=0`（关闭）；Cowork 服务的启动类型为自动。它们是这台电脑当时的结果，不能当作所有电脑的默认值。

### 在新电脑上手动查看

1. 按 **Ctrl + Shift + Esc** 打开任务管理器。
2. 进入 **启动应用／Startup apps**，查看 Claude 是否启用。也可以查看 **Windows 设置 → 应用 → 启动**。
3. 进入任务管理器的进程页面，查看是否仍有 Claude 主程序。
4. 要单独看后台服务，可按 **Win + R**，输入 `services.msc` 后回车。
5. 找到显示名称为 **Claude** 的服务，打开属性，核对“服务名称”是否为 `CoworkVMService`，再查看启动类型和当前状态。

这里是查看方法，**不用为了照抄旧电脑结果而停用服务**。Cowork 服务属于本地虚拟机相关组件；是否需要它取决于使用功能。服务运行本身不能证明账号正在联网，也不能证明它会导致 KYC。

如果启动应用里找不到 Claude，不能直接断言它没有任何后台组件，还需要区分安装方式、后台服务和其他启动途径。

## 9. 退出后能不能切换 IP 做别的事情

可以为其他事情正常切换网络，不需要让整台电脑永远固定一个 IP。但要分清以下情况：

- **关闭窗口：**点右上角 ×，程序可能仍在系统托盘或后台运行。
- **完全退出：**通过应用的退出菜单／托盘菜单退出；必要时用任务管理器确认。不要结束仍有未保存工作或正在执行任务的程序。
- **其他客户端：**如果另一个浏览器配置、Claude Code、编辑器插件或其他设备还在使用 Claude，它们仍可能独立联网。

Chrome 是否在关闭窗口后继续后台运行，取决于它的后台应用设置和扩展。不要默认“浏览器窗口不见了”就等于相关通信已经停止。

从网络原理上说，没有相关客户端向 Claude 发请求时，仅切换本机 IP，不会自动把新 IP 上报给 Claude。下次重新连接时，Claude 会看到当时的出口 IP，并可能结合其他信号判断位置。

**当前没有依据说普通换 IP 必然封号，也没有依据保证固定 IP 永远不再验证。** Cowork 当时没有观察到网络连接，只是短时检查结果；此次没有长期监控，也没有修改防火墙或禁用服务。

## 10. 哪些结论不要从这次经历里推出来

- “旧 Google 账号触发了 Persona，所以该 Google 账号肯定不能用了。”——没有这样的证据。
- “第三方检测拿到高分，Claude 就一定不会验证。”——分数不是 Anthropic 的决策依据。
- “把菜单、字体、时区改成美国风格，就满足使用地区要求。”——这些设置不能改变实际所在地。
- “没有看到服务联网，所以它永远不联网。”——短时检查不能支持这个结论。
- “注册时没验证，以后就不会验证。”——注册成功只说明当时的结果。
